📊 Model Analysis

4 Models Compared

All four models use the same pipeline: KNN Imputer → Robust Scaler → Classifier. Here's how their performance compares on the Pima test set.

💡 Why KNN Appears Twice

This is one of the most interesting aspects of this project — the KNN algorithm is used in two completely separate roles:

Role 1 — Inside every pipeline

KNNImputer (k=5)

The Pima dataset has "fake zeros" where missing values were recorded as 0 (e.g. Glucose=0, BMI=0). These are biologically impossible. KNNImputer replaces them by finding the 5 most similar real patients and averaging their actual values. This runs before every model trains.

Role 2 — One of the 4 classifiers

KNeighborsClassifier (k=11)

For prediction, KNN finds the 11 most similar patients in the training data and lets them "vote" — diabetic or not. Closer patients get more voting weight (distance-weighted). k=11 is odd to avoid tie votes. This is the standalone KNN model competing against the other 3.

💡 When to Use Each Model
GB

Gradient Boosting

Best at complex non-linear patterns. Each tree corrects the previous one's mistakes. Can overfit on small datasets but usually very accurate.

RF

Random Forest

200 independent trees trained on random subsets, then votes. Very robust. Handles class imbalance well with balanced weights. Hard to overfit.

LR

Logistic Regression

Linear model. Fast, interpretable, gives well-calibrated probabilities. Excellent AUC baseline but struggles with non-linear feature interactions.

KNN

KNN Classifier

No training phase — just memorises all patients. At prediction time, finds 11 nearest neighbours. Sensitive to scaling, hence RobustScaler is critical.

🧬 Feature Analysis

Feature Dependency Analysis

We removed one feature at a time, retrained all 4 models, and measured the AUC drop vs baseline. A large positive drop = the feature was important. Negative = removing it actually helped (noisy/redundant feature).

⚙️ Technical Pipeline

How GlycoSense Works — Step by Step

From raw CSV to live prediction in the browser.

1

Load CSV

Read diabetes.csv — 768 Pima Indian women, 9 columns, from UCI ML Repository / Kaggle.

2

Fix Fake Zeros

5 columns use 0 for missing data. Replace with NaN: Glucose, BloodPressure, SkinThickness, Insulin, BMI.

3

KNN Imputer

Role 1 of KNN: fill NaN using 5 nearest patients. Preserves real clinical correlations unlike mean imputation.

4

Feature Engineering

Create 5 new features: Glucose×BMI, Age×Pregnancies, Insulin÷Glucose, BMI×Age, WHO Glucose category.

5

Robust Scaling

Scale using median + IQR — resistant to extreme lab outliers unlike StandardScaler.

6

Train 4 Models

Gradient Boosting, Random Forest, Logistic Regression, KNN Classifier — all 5-fold cross-validated.

7

Feature Dependency

Drop each feature → retrain all 4 → compare AUC. Quantifies each variable's real contribution.

8

Flask API

All 4 pipelines saved as .pkl files. Flask serves predictions at /predict, metadata at /meta.
